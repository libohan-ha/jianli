## 1. 项目概述

### 1.1 项目名称

**基于大模型的智能简历分析与优化平台**（AI Resume Analyzer & Optimizer）

### 1.2 项目简介

本平台是一款基于人工智能大语言模型（LLM）的智能简历分析工具。用户可上传 PDF 格式的简历文件，系统通过 AI 技术对简历内容进行深度分析，从 HR 专业视角提供评分、优化建议，并以直观的 Diff 对比视图展示修改方案，最终支持一键导出优化后的简历。

### 1.3 项目目标

| 目标维度     | 具体目标                                            |
| ------------ | --------------------------------------------------- |
| **用户价值** | 帮助求职者快速提升简历质量，提高面试通过率          |
| **商业价值** | 建立 AI+招聘领域的产品基础，为后续增值服务铺垫      |
| **技术价值** | 验证 LLM 在垂直领域的应用能力，积累 AI 产品研发经验 |

### 1.4 核心功能概览

```
┌─────────────────────────────────────────────────────────────┐
│                    智能简历分析平台                          │
├─────────────────────────────────────────────────────────────┤
│  📄 文件上传    →   🤖 AI分析    →   📊 对比展示   →   📥 导出  │
│  ──────────     ──────────     ──────────     ──────────   │
│  PDF解析        HR视角打分      Diff视图       PDF/MD      │
│  文本提取       优化建议        高亮修改       一键生成     │
└─────────────────────────────────────────────────────────────┘
```

## 2. 市场背景与痛点分析

### 2.1 市场背景

- **就业市场竞争激烈**: 每年数百万应届毕业生进入职场，简历竞争压力巨大
- **HR 筛选时间有限**: 平均每份简历的初筛时间仅 6-10 秒
- **AI 技术成熟**: GPT-4、DeepSeek 等大模型在文本理解和生成方面表现优异
- **在线求职普及**: 超过 80%的求职者通过网络渠道投递简历

### 2.2 核心痛点

| 痛点             | 描述                                         | 影响程度   |
| ---------------- | -------------------------------------------- | ---------- |
| **简历撰写困难** | 求职者不知道如何突出自身优势，简历同质化严重 | ⭐⭐⭐⭐⭐ |
| **缺乏专业反馈** | 难以获得 HR 视角的专业评估和改进建议         | ⭐⭐⭐⭐⭐ |
| **修改效率低下** | 多次修改迭代耗时费力，缺乏对比参照           | ⭐⭐⭐⭐   |
| **格式问题繁琐** | 排版、格式调整占用大量时间                   | ⭐⭐⭐     |

### 2.3 解决方案优势

1. **AI 赋能**: 利用大语言模型的强大理解能力，提供专业级分析
2. **即时反馈**: 秒级响应，快速获得完整的分析报告
3. **可视化对比**: Diff 视图清晰展示每一处修改建议
4. **一站式服务**: 从分析到导出的完整闭环

## 3. 目标用户

### 3.1 用户画像

#### 主要用户群体

| 用户类型       | 特征描述                             | 核心需求           | 使用频率       |
| -------------- | ------------------------------------ | ------------------ | -------------- |
| **应届毕业生** | 22-25 岁，初次求职，缺乏简历撰写经验 | 需要从零开始的指导 | 高频（求职季） |
| **职场新人**   | 1-3 年工作经验，寻求跳槽机会         | 需要突出项目经验   | 中频           |
| **转型求职者** | 跨行业/跨岗位求职者                  | 需要重新包装技能   | 中频           |
| **HR/猎头**    | 招聘从业者                           | 批量优化候选人简历 | 高频           |

### 3.2 用户场景

**场景一：应届生小王**

> 小王是计算机专业大四学生，准备投递互联网公司。他对自己的项目经历描述没有信心，不知道是否突出了技术亮点。通过本平台，他上传简历后，AI 从技术面试官角度给出了评分和具体修改建议，帮助他优化了项目描述的表达方式。

**场景二：跳槽者小李**

> 小李有 3 年 Java 开发经验，想跳槽到大厂。他的简历内容较多但重点不突出。使用平台后，AI 帮他精简了不相关的内容，强化了核心项目的 STAR 描述法，并用 Diff 视图清晰展示了所有修改点。

## 4. 产品定位

### 4.1 产品定位语

**"让每一份简历都值得被看见"**

### 4.2 竞品分析

| 竞品           | 优势               | 劣势                     | 我们的差异化         |
| -------------- | ------------------ | ------------------------ | -------------------- |
| 某在线简历工具 | 模板丰富，知名度高 | 无 AI 分析，仅提供模板   | AI 深度分析+优化建议 |
| 某 AI 写作助手 | 通用 AI 能力强     | 非垂直场景，缺乏 HR 视角 | HR 专业视角打分评估  |
| 某简历优化服务 | 人工服务专业       | 费用高，响应慢           | 即时响应，性价比高   |

### 4.3 核心竞争力

1. **垂直场景优化**: 专为简历场景设计的 Prompt 工程
2. **专业角色扮演**: AI 以 HR/面试官视角进行分析
3. **可视化对比**: 清晰的 Diff 视图展示修改建议
4. **完整闭环**: 分析 → 建议 → 修改 → 导出一站式完成

### 5.2 模块一：文件上传与解析

#### 5.2.1 功能描述

用户可上传 PDF 格式的简历文件，系统自动提取文本内容，为后续 AI 分析做准备。

#### 5.2.2 详细需求

| 需求 ID | 需求描述          | 优先级 | 验收标准                   |
| ------- | ----------------- | ------ | -------------------------- |
| UP-001  | 支持 PDF 文件上传 | P0     | 支持 ≤10MB 的 PDF 文件     |
| UP-002  | 文件格式校验      | P0     | 非 PDF 文件提示错误信息    |
| UP-003  | 上传进度展示      | P1     | 显示上传百分比进度条       |
| UP-004  | PDF 文本提取      | P0     | 准确提取 PDF 中的文本内容  |
| UP-005  | 提取结果预览      | P1     | 用户可查看和确认提取的文本 |
| UP-006  | 文本编辑修正      | P2     | 用户可手动修改提取的文本   |
| UP-007  | 拖拽上传支持      | P1     | 支持拖拽文件到上传区域     |

#### 5.2.3 业务规则

- 单次只能上传一个文件
- 文件大小限制：10MB
- 支持格式：PDF（后续可扩展 DOCX）
- 提取失败时提供手动输入入口

#### 5.2.4 异常处理

| 异常情况 | 处理方式 | 提示信息                               |
| -------- | -------- | -------------------------------------- |
| 文件过大 | 拒绝上传 | "文件大小超过 10MB 限制，请压缩后重试" |
| 格式错误 | 拒绝上传 | "仅支持 PDF 格式，请上传正确的文件"    |
| 解析失败 | 降级处理 | "PDF 解析失败，请手动粘贴简历内容"     |
| 网络中断 | 重试机制 | "网络异常，正在重试..."                |

### 5.3 模块二：AI 对话分析

#### 5.3.1 功能描述

调用大语言模型 API（OpenAI/DeepSeek），让 AI 以 HR 或面试官角色对简历进行深度分析，提供评分和优化建议。

#### 5.3.2 详细需求

| 需求 ID | 需求描述     | 优先级 | 验收标准                 |
| ------- | ------------ | ------ | ------------------------ |
| AI-001  | 综合评分     | P0     | 提供 1-100 分的综合评分  |
| AI-002  | 维度评分     | P0     | 提供 5 个维度的细分评分  |
| AI-003  | 问题诊断     | P0     | 列出简历存在的主要问题   |
| AI-004  | 优化建议     | P0     | 提供具体的修改建议       |
| AI-005  | 修改后文本   | P0     | 生成优化后的完整简历文本 |
| AI-006  | 流式响应     | P1     | 分析结果逐字流式展示     |
| AI-007  | 目标岗位定制 | P1     | 根据目标岗位定向优化     |
| AI-008  | 多轮对话     | P2     | 支持追问和深入分析       |

#### 5.3.3 评分维度设计

| 维度           | 权重 | 评估要点                                   |
| -------------- | ---- | ------------------------------------------ |
| **内容完整性** | 20%  | 基本信息、教育背景、工作经历、技能等完整度 |
| **表达清晰度** | 25%  | 语言表达是否清晰、逻辑是否通顺             |
| **量化成果**   | 25%  | 是否有具体数据支撑、成果是否量化           |
| **关键词匹配** | 15%  | 与目标岗位的关键词匹配程度                 |
| **格式规范**   | 15%  | 排版、格式是否规范专业                     |

#### 5.3.4 AI Prompt 设计规范

**系统角色设定**:

```
你是一位拥有10年经验的资深HR，专注于互联网/科技行业招聘。
你的任务是从招聘者视角分析简历，提供专业的评估和改进建议。
请严格按照以下JSON格式输出分析结果。
```

**输出格式规范**:

```json
{
  "overallScore": 75,
  "dimensions": {
    "completeness": { "score": 80, "comment": "..." },
    "clarity": { "score": 70, "comment": "..." },
    "quantification": { "score": 65, "comment": "..." },
    "keywords": { "score": 75, "comment": "..." },
    "format": { "score": 85, "comment": "..." }
  },
  "problems": [
    { "type": "critical", "description": "...", "location": "..." },
    { "type": "major", "description": "...", "location": "..." }
  ],
  "suggestions": [
    {
      "category": "工作经历",
      "original": "...",
      "optimized": "...",
      "reason": "..."
    }
  ],
  "optimizedResume": "完整的优化后简历文本..."
}
```

#### 5.3.5 LLM 服务配置

| 配置项      | 推荐值                | 说明           |
| ----------- | --------------------- | -------------- |
| 模型选择    | gpt-4 / deepseek-chat | 主模型         |
| Temperature | 0.3                   | 保持输出稳定性 |
| Max Tokens  | 4000                  | 确保完整输出   |
| 超时时间    | 60 秒                 | 最大等待时间   |

## 9. 验收标准

### 9.1 功能验收标准

| 模块      | 验收条件      | 通过标准            |
| --------- | ------------- | ------------------- |
| 文件上传  | 上传 10MB PDF | 5 秒内上传成功      |

## 11. 风险评估

| 风险             | 可能性 | 影响 | 应对措施               |
| ---------------- | ------ | ---- | ---------------------- |
| LLM API 不稳定   | 中     | 高   | 多服务商备份，本地缓存 |
| PDF 解析不准确   | 中     | 中   | 提供手动编辑入口       |
| 分析结果质量不佳 | 中     | 高   | 持续优化 Prompt        |
| 并发性能瓶颈     | 低     | 高   | 队列+限流机制          |
